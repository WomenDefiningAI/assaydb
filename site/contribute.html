Contribution validation for each PR: our process.

Independent validation compares a candidate with a pinned baseline on Test Mini. Maintainers review the exact source, full outcomes and measurement conditions before accepting evidence. Every PR considered for merge needs the required suite evidence; missing evidence blocks merge. GitHub checks alone do not establish this gate.

  • SLT (SQLLogicTest): known SQL inputs and expected answers from the SQLite project. We retain the fixed corpus, exclusions and nonpasses.
  • hunt55K: 55,000 generated differential queries compare engine behavior with independent reference answers. Our public generators and frozen-scope documentation explain what is and is not available.
  • SF10 correctness: check all 22 analytical queries on roughly 10 GB, including worker and resource cases, before interpreting speed. See TPC-H background and our input and method limits. These are research measurements, not audited TPC-H results.
  • SF10 timing: repeat the same workload with pinned tools, inputs and settings. Retain warmups, timed samples, failures and slower queries; distinguish total time from geometric mean.
  • Retail real-world tests: original analysis, product variants and decimal edge cases exercise practical SQL on real and synthetic fixtures. See the UCI Online Retail source and our public SQL and documentation; raw customer rows and frozen reference answers are not bundled.

Standard checks and a small acceptance suite complement these workloads. Passed, unsupported, wrong, error, excluded and not-run outcomes stay separate. Retained measurements require a reviewed source-equivalence check; execution changes need fresh runs. Technical workflow and evidence rules.

Machine-readable reviewed evidence

People building the engine.

Contributions count as completed here only after their pull request is merged into the public engine’s main branch. The list is loaded from public GitHub activity. Each entry shows the PR author, title, number and merged date; meaningful testing contributions are included. This is credit for merged work, not a correctness certificate or an accepted benchmark result.

Accuracy shows applicable SQL tests passed, with the count, denominator and failure breakdown. Speed shows paired suite wall time faster or slower than tested main on the same host and configuration. “Not measured” means no reviewed evidence for that metric; a Polars ratio is not a PR improvement against main.

    What appears here

    We check public pull requests for changes to engine or Python binding code, correctness tests, benchmark methods, or formal-verification source files. We use specific file paths, not PR titles, to select changes. Imported Alpha release commits, routine website or setup-only changes, and unmerged work do not count.

    Other commit authors are shown only when GitHub links their authored commits to a public account, with a link to that commit. Bot accounts are labeled separately. Reviews, comments, merge commits and unlinked author names do not establish collaboration here.

    This is recent activity, not a complete contributor directory. We scan the most recently updated closed pull requests and show up to 12 qualifying changes. GitHub limits and unavailable responses can leave the list incomplete. The GitHub link includes all merged pull requests, including website work.
