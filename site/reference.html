Side experiment / reference evaluator

A simpler engine.
A clearer set of rules.

A separate, slower implementation with proved properties for selected SQL operations. It helps us study the rules and compare answers on supported cases.

The reference evaluator is not publicly released. Release timing is still to be decided.

A checking tool alongside the fast engine.

The reference is not the core engine in the alpha packages. Comparing its answer with another engine can catch a disagreement. Agreement on one execution is a test; it does not prove that other engine.

Specific properties, with explicit boundaries.

A feature name is not a proof statement. The useful question is what the implementation has been shown to preserve.

DISTINCTEvery present row appears exactly once, retaining the first occurrence.
AggregatesWhole-table aggregates return one row. COUNT ignores NULL arguments; empty input gives COUNT 0 and SUM, MIN and MAX NULL.
ORDER BY / LIMITOrdering gives a sorted rearrangement of the input and keeps ties stable. LIMIT keeps the first n rows.
IN subqueriesMembership matches values from rows whose WHERE is TRUE, under SQLite NULL rules. NULL IN an empty result is FALSE; NOT IN is TRUE.
Versions, assumptions and sources

The historical reference measurements reach development version v11. An earlier source-only experiment linked v9. The evaluator and its proof workspace are not part of the public repository or packages; the Python and Rust alpha packages contain the fast engine only.

Exact decimal comparisons with SQLite floating-point behavior still rely on a stated, unproved admission argument. Parsing, translation, setup, comparison, compilers and proof tools remain separate trusted parts. The coverage percentage does not remove these assumptions.
