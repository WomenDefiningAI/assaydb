Side experiment / reference evaluator

A simpler engine.
A clearer set of rules.

We built a simpler program to study how SQL should work. It is slower than the main engine, but selected operations have computer-checked proofs. It can also provide comparison answers for supported questions.

The reference evaluator is not publicly released. Release timing is still to be decided.

A checking tool alongside the fast engine.

A supported SQL query → Reference evaluator → A comparison answer

This reference program is separate from the engine in the alpha packages. Comparing their answers can reveal mistakes. Matching answers on a test do not prove that the fast engine is always correct.

The measurements below tested only the reference program. They did not compare it with the fast engine.

How far does the reference reach?

How much of the test collection could the reference handle with matching answers? The collection has 7,421,339 records in 622 files. A record is one entry in those test files.

No wrong outcomes were observed in these reference runs. The fast engine was not checked in these runs, so these results make no correctness claim about it.

Specific properties, with explicit boundaries.

A proof needs a precise rule. Here are examples of the rules checked for selected reference operations. NULL means a missing value in SQL.

DISTINCTDISTINCT removes repeated rows. Each different row appears once, keeping its first occurrence.
AggregatesAggregates summarize a table in one row. COUNT counts non-NULL values. With no input rows, COUNT returns 0; SUM, MIN and MAX return NULL.
ORDER BY / LIMITORDER BY sorts the rows without losing or adding any. Tied rows keep their relative order. LIMIT keeps only the requested number of rows from the start.
IN subqueriesIN asks whether a value appears in the result of another query. The proof follows SQLite’s rules for missing values and includes only rows where WHERE is TRUE. For an empty result, even NULL IN returns FALSE, and NULL NOT IN returns TRUE.
Versions, assumptions and sources

The historical reference measurements reach development version v11. An earlier source-only experiment linked v9. The evaluator and its proof workspace are not part of the public repository or packages; the Python and Rust alpha packages contain the fast engine only.

There are limits. Decimal comparisons still rely on an unproved assumption about which inputs safely match SQLite’s number behavior. The code that reads SQL, translates it, prepares data and compares answers is trusted separately, as are the compiler and proof tools. A higher coverage percentage does not remove those assumptions.
